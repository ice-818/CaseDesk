# 自进化人审工作台（前端）实现与验证证据

- 日期：2026-11-25
- 范围：把后端的自进化状态机、fail-closed 门禁、错例沉淀与回归集版本管理，暴露为 operator 可在浏览器中操作的可视化工作台，同时保持"人审不可绕过、机器只做确定性环节"的边界。

## 1. 目标

后端已有完整的六阶段状态机与两个失败终态，但只能通过 HTTP 调用。人审工作台要让 operator 在一个界面内完成：查看提案与错例对话、推进机器步骤、做人工批准/驳回、确认晋升、执行错例沉淀，并审查回归集的草稿版本。

工作台**不改变任何后端规则**：前端只是把确定性步骤的触发与人工决策的录入可视化，所有状态校验、权限判定、门禁与去重仍由服务端执行。

## 2. 页面结构

新增 `frontend/src/components/EvolutionPanel.tsx`，仅 operator 可见，从顶栏"自进化人审"进入。

| 区块 | 能力 |
| --- | --- |
| 改进提案（左） | 填写名称/版本创建提案（触发低分反馈收集）；列出全部提案，带状态徽标，点击选中 |
| 提案详情（右） | 展示基本信息、错例完整对话（用户/客服逐轮）、归因结果、门禁结果；按当前状态只显示该阶段可执行的下一步 |
| 回归集版本管理（底部） | 列出全部意图回归集版本与用例数；对 `draft` 版本录入审核说明并冻结/驳回 |

阶段操作按状态机线性呈现，且与后端守卫一一对应：

```
collect → 执行归因
attribute → 选择已批准回归集 + 候选意图/关键词 → 运行回归
regress → 执行门禁
gate → 录入审核说明 → 人工批准/驳回
review → 确认晋升
promoted → 录入新版本号 → 错例沉淀
blocked / rejected → 终态提示，不可推进
```

候选意图以下拉选择（14 个 `IntentLabel`），避免手输枚举错误；候选关键词与各审核说明仍需人工填写，关键写操作在缺少必填项时按钮禁用。

## 3. 新增后端只读端点

为支撑前端选择回归集与查看错例，新增两个 operator 只读端点，不改变任何写路径：

- `GET /admin/evolution/regression-datasets`：列出全部意图回归集版本（含状态与用例）。
- `GET /admin/evolution/proposals/{id}/feedback-cases`：返回该提案重建的错例集（含逐轮对话）。

写路径（attribute/regress/gate/review/promote/consolidate、回归集 review）完全复用既有端点与服务端校验。

## 4. 安全与边界

- **权限**：路由与后端均要求 operator；buyer/service_agent 无法进入，前端入口与后端 `require_operator` 双重保证。
- **人审不可绕过**：前端没有任何"一键自动通过/上线"，批准、晋升、冻结均为独立人工动作；后端状态机对非法转换返回 `409`。
- **凭证处理**：请求经统一 `apiRequest` 携带 Bearer 令牌，凭证不会出现在 URL；401 自动失效、403 给出权限提示，失败写操作不自动重试。
- **离线零付费**：前端只调用本机/内网 API，后端外部 API 调用为 0，不引入任何新的付费能力。
- 不做 LLM 自动生成 Prompt、不自动上线；不做真实支付/资金移动。
