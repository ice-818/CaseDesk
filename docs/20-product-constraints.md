# 商品推荐硬条件：第一阶段

搜索与推荐工具支持 min_price_cents、max_price_cents（整数分，含边界）、color、size。
参数非法或最低价高于最高价时拒绝执行，未知参数也拒绝，防止 budget 等字段被静默忽略。
SQL 同时过滤传入的条件和可用库存，再按 SKU 排序取前 N 条；不再先取五条候选后筛选。
category 与 query 同时传入时取交集，query 应是商品关键词，不能是完整自然语言问题。
无匹配为一次成功查询，返回空列表；不是异常，不应触发放宽条件的重试。

## 商品规格约定

当前数据库没有变体表，第一阶段沿用 tags 存放明确规格：
`通勤,color:黑色,size:42`。一条 SKU 必须对应一种实际可购买的颜色与尺码及其库存。
缺少对应标签时无法证明满足条件，必须排除；商品文案中的“42码”不作为规格字段。
不能给同一SKU标注多个颜色/尺码来表达所有组合；生产级目录后续需要单独的变体表。
此次不改现有数据库内容，也不凭空给旧商品补规格。

## 验证边界

真实 SQLite 集成测试覆盖超预算、错色错码、缺失规格、零库存、精确尺码匹配、
价格边界、LIMIT之前过滤、类别和关键词交集以及通配符转义。
回答提示词约束不得在空结果时虚构商品或放宽条件，但提示词不是程序级保证。

## 第二阶段：状态、执行和返回结果的检查

`product_requirements` 保存本轮用户原话与确定性解析的条件，独立于模型计划。
支持“300元以内”“预算300元”“不超过300元”、常见基本色名和“42码”等表述。
区间、近似预算、多个目标色/尺码和检测到的其他不支持表述会请求澄清。
不是任意自然语言理解器，不覆盖所有同义表达。

执行商品搜索/推荐前，用已确认的用户条件覆盖模型遗漏或改动的对应参数；
推荐降级到搜索时保留硬条件。返回结果再检查预算与规格标签，受约束推荐采用
确定性模板生成商品清单或无结果说明，不让模型自行补出其他商品。
知识库降级不能冒充已核实的商品候选。用途等非结构化偏好仍明确标为待核实。
澄清和已核验的商品清单不进入后续LLM忠实度改写，以免确定性结果被重写。

## 第三阶段：多轮选购任务

新增shopping_tasks表，按session_id持久化当前任务的商品关键词、条件、本轮原话及
待澄清原因；请求之间从数据库读取，不依赖模型根据聊天记录重建全部条件。
Alembic新增0005；启动create_all的演示库会自动创建新表。

已覆盖的明确表达：
- “白色也可以”：保留预算、尺码，颜色扩展为黑或白。
- “换成白色”：替换颜色，继续保留其他条件。
- “预算改成350元”：更新最高价，保留颜色和尺码。
- “颜色不限”：删除颜色条件，执行前也会删除模型自行补回的颜色参数。
- “再推荐一个耳机”：切换任务，清空旧预算、颜色、尺码；新任务明确提供的条件除外。
- 转入订单/物流/售后咨询或无关话题时保守结束当前选购任务，不继承旧条件。

搜索支持colors列表，列表内部为OR，与预算、尺码、商品关键词之间为AND。
每条SKU仍代表一个可售规格。单色color和多色colors不可同时传入。
明确的选购请求及后续条件编辑走AGENT路径，并用固定的受约束推荐计划执行，
避免“白色也可以”被单句意图识别误判，或把该句原样作为商品搜索关键词。
这是确定性多轮工作流，不是新增了执行后自主重规划Loop。

关键词识别目前仅支持鞋、跑步鞋、通勤鞋、运动鞋、耳机、帽子、T恤、杯子等有限词表。
任务切换和编辑是保守规则，不声称覆盖任意自然语言；复杂条件、取消条件同义表达、
颜色组合表达仍需继续补用例。当前每个会话只保存一个当前选购任务，没有多任务切换恢复。
并发编辑同一会话的版本冲突控制尚未实现。已用真实SQLite和离线聊天API做多轮验证，
未调用真实模型端到端评测，不能宣称推荐链路对所有表达零违规。
