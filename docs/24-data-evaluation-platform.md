# 数据中台与评测中台：最小可运行版本

前端顶部“数据与评测”进入管理页面。默认示例是人工合成的多轮改色用例，
不是线上数据或系统性能证明。可创建数据版本、审核、运行评测、查看逐题结果和成对比较。

## 数据中台

管理DatasetVersion：名称、版本、任务、development/regression/heldout划分、来源类型、
来源说明、许可证、分组ID、参考答案、样本及内容SHA-256。每版最多50题，导入时结构校验。
拒绝重复题ID、完全相同输入、未知参考SKU和同名同版本；同一家族跨划分检查group_id重叠。
这是提交者分组和精确输入去重，不是自动语义去重；跨不同家族的泄漏仍需人工审查。

数据默认draft，填写审核人、说明后approved或rejected。已审核版本不能覆盖或修改，
修订需新版本。同名不同版本保持同一种任务。审核人是管理员填写的信息，没有独立多人审批。
heldout标签不证明从未被查看。reviewed_feedback为人工审核后的来源标签，尚未自动导出会话错例。

## 评测中台

只运行批准的冻结版本，保存run_id、数据版本/哈希、源码指纹、Python版本、评测协议、
运行标签、实际值、期望值、逐题耗时、异常类型、通过率与P95。异常题计入失败分母。
P95包含用例夹具准备，不是线上Agent接口延迟。标签只是备注，不能靠改标签切换模型或旧代码。
实际执行当前服务加载的组件；比较历史代码需在对应版本部署运行，并保留历史报告。
源码指纹不是已提交Git版本或完整环境归档。

首版适配器：
- product_search：冻结目录写入独立内存SQLite，调用真实find_matching_products，对比前3个SKU。
  各题目录事务回滚，不接触实际店铺目录或订单。
- shopping_update：真实调用update_requirements，对比逐轮更新后的条件、任务、活动状态、
  是否需澄清及属性依据要求。这是组件回归，不是LLM或整条Agent效果评测。

不调用外部模型API，无模型费用。原100题意图、65题生成、Bitext仍使用原命令行，尚未接入。
同一数据版本、同一评测协议的已完成运行可比较改善题、退化题、未变题和通过率差。
没有自动发布、自动Prompt优化或自动上线门槛。

## 接口与部署

接口前缀`/api/v1/admin/platform`，沿用require_admin和x-admin-token；生产无令牌禁用，
开发无令牌可访问。页面令牌只存在组件内存，离开页面丢弃。
- GET/POST /datasets；GET /datasets/{id}；POST /datasets/{id}/review。
- GET/POST /runs；GET /runs/{id}；GET /compare?baseline=...&candidate=...。

新增dataset_versions、evaluation_runs表及0007迁移；演示库create_all可创建新表。
API在请求中同步完成有界评测，执行前持久化running；没有队列、取消、重启续跑、自动清理
或分布式调度，崩溃可能留下running。列表默认最近50条，最大100条。
前端测试与构建不等于浏览器交互验收，仍需手动检查管理页。

这是共享版本数据与评测控制台首版，不宣称大规模企业数据湖、实时ETL、多租户或评测集群。
后续按实际需求接入反馈审核、知识版本和模型评测。
