# 受限商品选购Loop

当前主图新增 `execute_tools → check_shopping`，仅对active选购任务启用；
检查节点根据结果选择查只读商品详情、召回下一批候选，或进入最终回答。
其他业务仍沿原有计划执行，不会回到自由规划器，也不增加任何写工具权限。

推荐每批最多 3 个候选，关键词搜索每批最多 5 个。先按店铺权限、库存和硬条件过滤，
再按 SKU 排序分页。每个 SKU 最多查一次详情，核对当前价格、规格标签、库存
和明确的属性依据。当前属性只支持“防滑”，要求详情中有明确`feature:防滑`标签。
名称或描述提及防滑不作为可靠结构化依据；目录标签也不是检测认证或性能保证。

受约束任务绕过执行器的隐式跨工具fallback，继续决策由检查节点负责，避免绕过
查询预算或在商品查询失败后用知识库代替真实商品。
召回完整性指在预算内，已核验数量未达到 `SHOPPING_VERIFIED_TARGET`（当前为 3）时，
当前页核验完毕就继续补召回。遇到短页或空页，且该批候选已核验完毕，表示当前过滤条件下的目录已扫完。

- `completed` 在核验到目标数时立即返回，后续页和不会展示的候选无需再查。目录耗尽时如果已有合格候选，也返回 `completed`，展示已有结果。
- `no_match` 表示在当前授权范围与条件下已扫完且没有任何候选通过核验。
- `budget_exhausted` 表示尚未达到目标，且已达到工具调用次数与总步数上限中较小者，或检查时已用完 30 秒继续执行预算。该时间检查不会强制中断已在执行的调用。
- 缺少执行结果或工具报告失败时返回 `tool_failure`，条件需要澄清时返回 `needs_clarification`。
不重复查询已查SKU，不自动放宽条件。

状态 `shopping_loop` 保留候选、已查 SKU、核实结果、每轮工具名和次数及停止原因，
以及首次召回的工具名、已召回行数和目录耗尽标记。
会话任务条件继续跨请求持久化。后续新增应用层快照与安全重放恢复，详见[选购检查点](23-shopping-checkpoint.md)；不是原节点精确续跑。
最终回复只列核实后的候选；达到上限时可返回已核实的部分并说明未完成核实。

当前搜索和详情查询均读本地商品库，所以补查通常不会凭空获得新属性信息；它可再次
核验商品详情及库存，缺少资料最终必须停下。尚未连接商家外部规格或检测资料。
这是结果驱动的确定性选购控制循环，不是任意任务的LLM自主重规划系统。

正式验收见 [分批召回集成测试](../tests/integration/test_shopping_recall.py)。预算充足时，
合格数低于目标（含 0）的用例验证扫到末尾、候选无遗漏，以及零合格时返回 `no_match`。
合格数超过目标的用例验证找够即停，不查多余页。合格数恰好等于目标时，也在核验到第 3 个时停止。

## 商品规则精排

SQL 的 SKU 顺序用于稳定分页。每次收到新一页，控制器对当前已召回的完整候选池重新评分，
优先核验尚未核验的最高分商品。通过核验的商品用最新详情评分，最终按分数降序展示。
同分按 SKU 升序。达到目标即停，所以排序覆盖当前已召回的候选，尚未读取的页不参与排序。

| 特征 | 权重 | 归一化规则 |
| --- | ---: | --- |
| 相关性 `relevance` | 40% | 用现有分词器切分查询。每个去重后的查询词取最强命中字段，名称 1、品类 0.65、普通或属性标签 0.5、未命中 0，再对查询词取平均。空查询为 0.5。 |
| 价格符合度 `price_fit` | 25% | 价格在预算的 75% 时得 1 分，向 0 元和预算上限两端线性递减至 0。无预算为 0.5。零预算且商品免费时为 1，超预算为 0。 |
| 库存 `inventory` | 10% | 将库存截断到 0–10，除以 10 后开平方。库存增加的边际收益递减，达到 10 件后得满分。零库存商品由召回过滤。 |
| 标签匹配 `tag_match` | 25% | 显式要求中被 `feature:<属性>` 精确命中的比例。无显式属性要求为 0.5。颜色和尺码由硬条件过滤和核验处理。 |

各项分数在 0–1 内，权重之和为 1，总分是四项分数的未舍入加权和。
`shopping_loop.candidate_ranking` 和 `shopping_loop.verified_ranking` 保留每个 SKU 的总分与分项，
可从选购检查点查看。评分仅决定核验与展示顺序，原有价格、规格、库存、属性核验和商家范围仍决定商品能否展示。

当前采用手工规则权重。`ProductRanker` 定义候选、选购要求与排序结果的接口，便于将来评估
并替换为学习排序（LTR）实现。SQL 分页与导购停止条件由各自的层负责。

## 多轮选购导航

首轮按精排顺序展示所有已核验商品，并分配稳定的展示序号。后续轮保存当前指针、已展示 SKU、
已选 SKU 和上次对比的 SKU。补召回可能改变精排顺序，已经分配的展示序号继续指向原 SKU。

| 指令 | 行为 |
| --- | --- |
| 换一个、下一个、再来一个、再换一个、换一款、还有吗、其他的呢、别的 | 移到下一件已核验商品。核验够 3 件时循环浏览。 |
| 上一个、前一个、刚才那个、回到上一个 | 移到上一件，已在首位时给出提示。 |
| 对比、比较、比对、对比这两个、对比第 N 和第 M | 默认对比当前与下一件已核验商品，也可指定两个已展示序号。给出价格、库存、标签和评分。 |
| 就这个、就选它、第 N 个、第 N 个吧、选第 N 个 | 记录当前已展示商品或指定 SKU。非法序号会要求澄清。 |

指令按整句匹配，支持阿拉伯数字和常见中文序号。“下不了单”“不要黑色”“上次的订单”等仍进入正常处理。
没有可恢复的选购结果时，请用户先描述要找的商品。导航沿用原任务的预算、规格和属性要求。

仅当用户到达末尾、核验数不足 3、仍有可查候选且预算允许时，才继续核验或补召回。
已耗尽请求次数或累计时间时，可继续浏览已核验商品。纯导航不扣调用次数，轮与轮之间的等待时间
不计入查询预算。目录耗尽和预算耗尽分别提示。

聊天导航读取同一会话的最新有效快照，校验版本、任务条件以及登录身份和商家范围。
普通结束的轮次从 `completed` 快照浏览，中断的轮次可保留已核验的进度。新快照的 `parent_id`
指向来源快照，旧版缺少身份范围标记的快照需重新发起选购。显式故障恢复接口仍按原需求重新查询。
导航展示的是快照中的已核验目录数据，价格和库存可能随目录更新。选择只记录 SKU，
导购范围限于只读查询和比较，不含个性化或交易执行。
